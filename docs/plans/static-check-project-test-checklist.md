# 最小静态检查脚本测试清单

## 基线

1. 在仓库根目录执行 `node tools/check-project.mjs`。
2. 预期：所有检查通过，退出码为 0；应识别当前 `snake55/index.html` 的 15 个脚本。

## 故障注入

以下每项均为临时改动，单项执行检查后立即恢复，再进行下一项。

1. 在 `snake55/` 临时加入语法错误的 `*.js` 文件。
   - 预期：语法检查列出具体文件和 Node 原因，退出码非 0。
2. 在 `snake55/` 临时加入包含真正 `import('x')` 或静态导入的 `*.js` 文件。
   - 预期：模块禁令检查列出文件和原始行号，退出码非 0。
3. 临时调换 `index.html` 中两个脚本的顺序。
   - 预期：脚本顺序检查失败并列出实际顺序与预期顺序，退出码非 0。
4. 临时修改一个脚本的 `?v=`。
   - 预期：缓存戳一致性检查列出不一致脚本，退出码非 0。
5. 临时在正式入口 Markdown 中加入不存在的本地链接。
   - 预期：Markdown 链接检查列出来源文件和目标路径，退出码非 0。

## 恢复与回归

1. 删除全部临时文件并恢复被注入的文档内容。
2. 再次执行 `node tools/check-project.mjs`，预期退出码为 0。
3. 检查 `git status --short`，预期只剩计划内新增/修改文件，不包含故障注入内容。

## 识别边界

- 模板字符串整体视为非代码区域，因此不会深入检查 `${...}` 中的模块词。
- 正则字面量与除法表达式存在极少数无法仅靠字符状态机完全区分的写法；检查器尽量依据前一处代码 token 判断，最终语法仍由 Node `--check` 裁决。
- Markdown 第一版只验证本地文件存在，不验证标题锚点；复杂嵌套 Markdown 目标以常规链接写法为覆盖边界。
