# 最小静态检查脚本

## 目标

提供一个不依赖 npm install 的 Node.js 提交前检查入口，尽早拦截脚本语法、加载顺序、缓存戳、模块语法和正式入口文档断链回归。

## 涉及文件及理由

- `tools/check-project.mjs`：新增无依赖检查器。
- `README.md`：补充开发者可直接执行的检查命令与退出码说明。
- `docs/workflow.md`：把检查器接入现有提交流程，避免只写在 README 中。
- `docs/plans/STATUS.md`：登记本计划与测试清单状态。
- `docs/plans/static-check-project-test-checklist.md`：记录验收与故障注入步骤。

## 具体改动点

1. 枚举 `snake55/` 下第一层 `*.js`，逐文件用 `process.execPath`、`spawnSync`、参数数组和 `shell: false` 执行 `--check`。
2. 用轻量字符状态机扫描业务脚本中的静态 `import/export`、副作用导入、动态 `import()` 与 `import.meta`，保留原始行号；字符串、模板字符串、单双行注释和常见正则字面量内容不作为代码扫描。
3. 从 `snake55/index.html` 提取带 `src` 的脚本，按当前正式基线校验 15 个文件的缺失、额外、重复、文件名和顺序，并校验每个脚本有 `?v=` 且所有缓存戳一致；不固定当前具体戳值。
4. 检查八个正式 Markdown 入口中的普通链接与图片链接，忽略外部协议、纯锚点、代码块和行内代码；按链接所在文件解析相对路径，按仓库根解析 `/` 路径，剥离 query/hash，并报告 URL 解码错误。
5. 汇总所有检查错误后统一输出，任何错误返回非零退出码，全绿返回 0；不自动修复。

## 不动的底层

- 不修改任何 `snake55/*.js`、玩法逻辑、`snake55/02_config.js`、`snake55/03_core.js`、`snake55/04_collision.js`。
- 不修改 `snake55/index.html` 的脚本加载顺序或现有缓存戳。
- 不加入 B-TUNE 语义分析、Bus 同名分析、裸数字扫描、构建系统或第三方依赖。

## 验收标准

- 正常：当前干净基线全绿；语法检查、模块禁令、15 脚本顺序/数量/缓存戳、入口 Markdown 链接均报告通过。
- 反向：分别注入 JS 语法错误、真正的 import/export、脚本顺序错误、缓存戳不一致、入口文档断链，检查器均执行完全部检查并返回非零；恢复后再次全绿。
- 工程：临时故障注入全部恢复；最终 `git status` 只包含本计划文件；未触碰 core/collision。

## 识别边界

该版本不是完整 JavaScript AST。模板字符串整体按字符串处理，模板插值中的模块词不会被扫描；正则/除法的极端歧义场景采用启发式判断。Node `--check` 仍负责最终语法裁决，限制与覆盖范围记录在测试清单中。
