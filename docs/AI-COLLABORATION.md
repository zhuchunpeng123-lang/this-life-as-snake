# 《此生为蛇》AI 协作规范

版本：v1.0

## 1. 总原则

项目统一采用：

**ChatGPT 决策/创作 → 用户确认 → Codex 工程落地 → 用户实机验收**

聊天记录不是项目真理源。正式确认的信息最终进入仓库文档。

一个主题只保留一个主要真理源，专项文档引用上层文档，不重复建立完整设定。

## 2. 总控 ChatGPT

负责：

* 产品方向
* 世界观
* 优先级
* 重大玩法取舍
* 跨模块协调
* 对抗性审查
* Codex任务定义

总控可以输出正式文档正文，但原则上不承担仓库落盘、Git和机械文件操作。

## 3. 专项 ChatGPT

包括美术、音频、UI、Boss等专项窗口。

负责：

* 在已确定方向内深入设计
* 输出方案和资源
* 专项审查

不得自行：

* 改变世界观
* 改变核心玩法
* 改变工程架构
* 建立与现有文档冲突的真理源
* 将自己创建的临时文件视为仓库正式文档

专项窗口需要更新正式规范时，只输出“建议正文/修改内容”，由用户确认后交 Codex 落盘。

专项 ChatGPT 不应被假设能够直接访问用户本地 Git 仓库。任务应尽量使用自包含上下文和用户主动上传的素材。

## 4. 美术专项

负责：

* 视觉方向
* 角色设计
* PNG / Master Pose
* 必要的 Sprite Frame
* 图标/UI Asset
* 美术一致性审查

不负责：

* Git
* 仓库目录管理
* 正式 Markdown 落盘
* Canvas代码接入
* 游戏逻辑修改

角色动画默认采用：

**关键 Pose → 程序动画 → 实机验证 → 必要时补 Sprite Sheet**

不默认制作大量逐帧动画。

## 5. Codex

Codex是工程执行者。

负责：

* 创建和修改仓库文件
* 实现代码
* 接入已确认素材
* Sprite Sheet拼装/播放
* 自动检查
* Git commit/push
* 必要索引更新

不得自主决定：

* 世界观
* 产品定位
* Boss身份
* 美术风格
* 未经确认的新玩法

收到已经确认的设计正文时，以忠实落地为主。

## 6. 文档真理源

* GDD：玩法与设计意图
* `WORLD-BIBLE.md`：世界观
* `ART-BIBLE.md`：未来全局视觉语言
* `BOSS-xxx-视觉设计规范.md`：具体Boss视觉
* `AGENTS.md`：工程/Codex硬规则
* `AI-COLLABORATION.md`：AI角色分工和工作流

## 7. 新窗口规则

新窗口：

1. 明确自己是总控、专项还是Codex执行；
2. 只接收当前任务必要上下文；
3. 不要求复制全部历史聊天；
4. 不自行扩张任务；
5. 跨领域问题返回总控裁定。

## 8. Token原则

高成本推理用于重大决策。

简单文档落盘、文件修改、明确工程任务优先使用低成本执行模型。

避免多个高推理窗口重复分析同一问题。

## 9. 输出原则

默认：

* 先给结论
* 内容精简
* 不重复背景
* 不进行无关扩展
* 用户未要求全面审查时不写长篇报告
