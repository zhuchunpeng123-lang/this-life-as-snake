# 《此生为蛇》通用验收方法

本文件只保留长期可复用的检查方法；一次性专项清单、旧 RC 和历史报告不作为默认入口。

## 通用 smoke

- 用项目现有方式或可靠的最简单静态 HTTP 服务启动 `snake55/`，不以 `file://` 作为浏览器验收依据。
- 确认入口加载、Canvas 存在、关键脚本无阻断错误；需要时检查控制台和资源 404。
- 修改 JS 后运行 `node tools/check-project.mjs`、相关 `node --check` 和 `git diff --check`。
- 对涉及状态重置、暂停、死亡、重开、结算或资源加载的改动，至少走一次完整主链路。

## 移动端

- 横屏、摇杆、HUD 安全区、按钮触控和窄屏布局按真实 viewport 检查。
- 关注固定 UI 是否遮挡 Canvas、文字是否可读、触控区域是否误触；桌面通过不代表移动端通过。

## iOS standalone / audio

### 日常 standalone smoke

至少验证冷启动、首次用户手势后的音频、基础战斗 SFX、暂停/恢复、后台返回、死亡/重开。

### 修改 Audio、启动或 lifecycle 后

额外对比 Safari 与 standalone，重复冷启动和首次解锁，检查后台/锁屏恢复。

### 发布前或故障排查

再扩展主屏重新进入、缓存/离线行为、多设备，以及记录 commit、设备型号和 iOS 版本。

基础音频解锁和系统静音条件已有对照证据；完整 standalone 主流程仍需按上述范围执行。音频检查关注语义事件 ownership、重复播放、voice/density、生命周期和手机外放可读性，不以某个历史音色为永久标准。

## 视觉与表现

- 默认由用户实机快速验收简单视觉调整。只有用户明确要求浏览器视觉证据时，才运行截图/录屏并实际读取结果。
- 需要视觉证据时，使用能证明结果的最小集合：匹配的前后状态、目标 viewport 或必要关键帧；证据不可用或不明确时标记阻塞。
- 视觉检查必须在真实尺寸、怪群密度和多技能共存条件下判断，不能只看静态大图或代码是否运行。

## 何时需要专项

- 改碰撞、伤害、波次、平衡、Boss 或移动端核心链路时，使用对应专项真理源和实机证据。
- 改音频事件、混音、生命周期或密度时读取 `docs/audio/AUDIO.md`。
- 改技能/Combo VFX 时读取对应 repo-local Skill；不要把专项一次性结论写成全项目永久规则。
